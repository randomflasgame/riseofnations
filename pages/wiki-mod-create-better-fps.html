CREATE BETTER FPS

Create Better FPS ist ein Performance-orientiertes Addon aus dem Create-Umfeld. Ziel ist es, die Darstellung und Verarbeitung großer Create-Aufbauten effizienter zu machen und unnötige Belastung bei umfangreichen Maschinenanlagen zu reduzieren.

01 // SYSTEM OVERVIEW

Was macht Create Better FPS?

Create erzeugt durch Zahnräder, bewegte Contraptions, Animationen und komplexe Maschinen deutlich mehr visuelle und technische Aktivität als ein gewöhnlicher Minecraft-Bereich.

Performance-Mods für das Create-Umfeld versuchen deshalb, unnötige Arbeit bei der Darstellung solcher Anlagen zu reduzieren.

CORE PRINCIPLE

Das Ziel ist nicht, Create-Maschinen abzuschalten, sondern ihre Darstellung möglichst effizient abzuwickeln.

02 // WHY CREATE CAN BE HEAVY

Warum Create-Anlagen Leistung benötigen

Eine große Fabrik besteht häufig aus hunderten oder tausenden miteinander verbundenen Blöcken und beweglichen Komponenten.

  • Zahnräder und Wellen.
  • Förderbänder.
  • Moving Contraptions.
  • Flüssigkeitssysteme.
  • Display- und Animationssysteme.
  • Große Maschinenhallen.
  • Viele gleichzeitig aktive Block Entities.
03 // FPS VS TPS

Client-FPS und Server-TPS unterscheiden

Ein wichtiger Punkt bei Performance-Problemen ist die Unterscheidung zwischen Grafikleistung und Spielsimulation.

PROBLEM BETROFFEN
FPS-Einbruch Client / Rendering
Spiel läuft langsam Server / Tick-System
Maschinen reagieren verzögert häufig Server-Ticks
Bild ruckelt bei Kamerabewegung häufig Client-Rendering
IMPORTANT

Ein höherer FPS-Wert löst keinen überlasteten Server. Umgekehrt kann ein guter Server-Tick trotzdem von einem schwachen Client nicht flüssig dargestellt werden.

04 // LARGE FACTORIES

Große Fabriken

Besonders bei RISE OF NATIONS können große Create-Anlagen schnell sehr umfangreich werden.

Eine Fabrik mit mehreren Produktionslinien, Zügen, Lagerhallen und beweglichen Maschinen sollte deshalb von Anfang an performancebewusst geplant werden.

  • Maschinen logisch gruppieren.
  • Unnötige Daueranimationen vermeiden.
  • Produktionsanlagen nicht überall gleichzeitig aktiv halten.
  • Große Fabriken sinnvoll auf mehrere Bereiche verteilen.
05 // CREATE CONTRAPTIONS

Contraptions und bewegliche Maschinen

Moving Contraptions können wesentlich komplexer sein als statische Create-Maschinen.

Besonders große bewegliche Konstruktionen sollten deshalb nicht unnötig dauerhaft laufen, wenn sie gerade keine Funktion erfüllen.

FIELD RULE

Eine Maschine, die gerade nicht gebraucht wird, muss nicht zwingend permanent laufen.

06 // VISUAL COMPLEXITY

Visuelle Komplexität reduzieren

Performance kann nicht nur durch einzelne Mods beeinflusst werden. Auch der Aufbau einer Fabrik spielt eine Rolle.

  • Keine unnötigen dekorativen Animationen in großen Mengen.
  • Maschinenbereiche logisch strukturieren.
  • Sehr große Ansammlungen beweglicher Komponenten vermeiden.
  • Unnötige Redundanz bei Maschinen verhindern.

08 // GRAPHICS SETTINGS

Grafikeinstellungen

Performance-Mods ersetzen keine sinnvollen Grafikeinstellungen. Bei einem schwächeren System können reduzierte Sichtweiten und Partikeleffekte deutlich helfen.

  • Render Distance sinnvoll einstellen.
  • Simulation Distance nicht unnötig hoch setzen.
  • Partikel bei Bedarf reduzieren.
  • Shader nur verwenden, wenn ausreichend Leistung vorhanden ist.
  • Große Fabrikbereiche nicht unnötig weit laden.
09 // DEBUGGING

Performance-Probleme analysieren

Wenn eine Fabrik plötzlich ruckelt, sollte zuerst ermittelt werden, ob das Problem vom Client oder vom Server stammt.

  1. FPS beobachten.
  2. Debug-Anzeige kontrollieren.
  3. Bereich mit vielen Maschinen verlassen.
  4. Prüfen, ob die FPS wieder steigen.
  5. Server-Tick-Leistung separat untersuchen.
  6. Problematische Maschinenbereiche identifizieren.
10 // SPARK

Zusammen mit Spark

Spark ist im Modpack vorhanden und kann bei der Analyse von Performance-Problemen helfen.

Wenn nicht klar ist, warum eine große Anlage Probleme verursacht, sollte nicht blind ein Mod entfernt werden. Zuerst sollte eine Messung beziehungsweise Profilanalyse erfolgen.

PROFESSOR METHOD

Erst messen, dann verändern. Performance-Tuning ohne Messung führt schnell dazu, dass das eigentliche Problem übersehen wird.

11 // MULTIPLAYER

Auf dem Server

Auf einem Multiplayer-Server ist besonders wichtig, zwischen Client- und Serverproblemen zu unterscheiden.

  • Client-FPS sind individuell.
  • Server-Ticks betreffen alle Spieler.
  • Große Maschinenanlagen können Serverlast erzeugen.
  • Unnötig dauerhaft laufende Systeme sollten vermieden werden.
12 // COMMON MISTAKES

Häufige Fehler

„Ich habe schlechte FPS, also ist der Server langsam.“

Nicht zwingend. FPS sind zunächst ein Client-Problem.

„Meine Maschine läuft langsam, also brauche ich mehr FPS.“

Eine verzögerte Maschine kann auch durch Server-Tick-Probleme verursacht werden.

„Mehr Performance-Mods sind immer besser.“

Nicht automatisch. Mods können miteinander interagieren, weshalb Änderungen kontrolliert und getestet werden sollten.

13 // FACTORY DESIGN

Performancefreundliche Fabrikplanung

  1. Produktionsketten zuerst planen.
  2. Maschinen nur in benötigter Anzahl bauen.
  3. Produktionsbereiche sauber strukturieren.
  4. Lager und Transportwege logisch anordnen.
  5. Unnötige Dauerbewegungen vermeiden.
  6. Große Anlagen modular bauen.
14 // RISE OF NATIONS APPLICATION

Einsatz im Modpack

Das Modpack kombiniert Create mit zahlreichen weiteren großen Systemen. Dadurch ist Performanceplanung besonders wichtig.

  • Create-Fabriken.
  • Große Zugnetzwerke.
  • Automatisierte Lager.
  • Flüssigkeitsanlagen.
  • Militärische Produktionsstätten.
  • Große Städte und Spielerbasen.
TACTICAL RECOMMENDATION

Baue große Industrieanlagen modular. So lässt sich leichter feststellen, welcher Bereich bei Problemen tatsächlich verantwortlich ist.

15 // PROFESSOR DOCTRINE

Das Wichtigste zum Mitnehmen

  • Create kann durch große bewegte Anlagen anspruchsvoll werden.
  • Create Better FPS konzentriert sich auf Create-nahe Performance.
  • FPS und Server-TPS sind unterschiedliche Probleme.
  • Große Fabriken sollten bewusst geplant werden.
  • Spark kann bei der Ursachenanalyse helfen.
  • Performance sollte gemessen und nicht geraten werden.
  • Ein gut geplantes Fabriklayout hilft langfristig mehr als blindes Optimieren.
FINAL PRINCIPLE

Die beste Performance entsteht nicht durch einen einzelnen Zauberschalter, sondern durch das Zusammenspiel aus Optimierungsmods, sinnvoller Weltplanung und kontrollierter Maschinenkomplexität.
